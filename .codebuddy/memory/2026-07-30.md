## KV offloading / connector 调研（续）

### Model Runner V2 的 KV cache 注册差异（重要发现）
- V1 (`vllm/v1/worker/gpu_model_runner.py:7457-7461`) 在 model runner 里显式分支：
  `prefer_cross_layer_blocks` 为 True 时调 `register_cross_layers_kv_cache`，否则 `register_kv_caches`。
- V2 (`vllm/v1/worker/gpu/model_runner.py`) 的 `initialize_kv_cache` 末尾只调
  `get_kv_connector(vllm_config, kv_caches_dict)`（509 行）。
- `get_kv_connector` (`v1/worker/gpu/kv_connector.py:116-123`) 返回 `ActiveKVConnector`，
  其 `__init__` (`gpu/kv_connector.py:47-56`) 内部**只调 `register_kv_caches`**，并带注释
  `# TODO: support cross_layers_kv_cache`（指向 PR #27743）。
- 结论：
  1. V2 间接仍调了 `register_kv_caches`（offloading 能工作，但走逐层 dict 注册）。
  2. V2 **完全没有调用 `register_cross_layers_kv_cache`**，即尚未接入 cross-layer / uniform
     KV cache 布局（`use_uniform_kv_cache` / `allocate_uniform_kv_caches` 优化路径）。
  3. 不衔接点：`offloading_connector.py:59-63` 的 `prefer_cross_layer_blocks` 返回 True，
     本应走跨层注册；V2 下只会退化成逐层注册，牺牲跨层批量传输效率。属于 V2 的 WIP/功能缺口，非 bug。
- 另：`offloading_connector.py` 的 `register_kv_caches`/`register_cross_layers_kv_cache` 仅做转发，
  真正逻辑在 `vllm/v1/kv_offload/cpu/worker.py` 的 `OffloadingConnectorWorker`。

### KV group 与 tensor 共享是两个正交概念（重要澄清）
- **KV cache group**（`kv_cache_config.kv_cache_groups`）：纯逻辑分组，用于 offloading 调度分类
  （SWA/full-attention、不同 block_size）。多个 group 不导致 layer 共享 tensor。
- **Layer 共享同一 tensor**：物理属性，由 `kv_cache_config.kv_cache_tensors[i].shared_by` 描述
  （源自 `attn_utils.py:567 get_shared_kv_cache_layers`，tied/shared KV 的层）。
  仅此时 `kv_caches[layer_name]` 才对多个 layer 返回同一 tensor。
- offloading `worker.py register_kv_caches` 三种情形：
  - 默认 per-layer（各层不同 tensor）；
  - 非 packed 的 `shared_by`（去重分支 225-279 行，单 CanonicalKVCacheTensor + 多
    CanonicalKVCacheRef 回指，断言 data_ptr/stride 一致）；
  - 跨层 packed（block_stride>0，提前 return 193-223 行，整块单一视图，所有 group 指向 tensor 0）。
- 共享时 `tensors` 列表该 tensor 仅出现一次，`group_data_refs` 中每个共享 layer 一条
  `CanonicalKVCacheRef` 指回同一 `tensor_idx`（各自带 unpadded_page_size_bytes）。

### DCP（Decode Context Parallel）与 prefix caching 的交互（重要澄清）
- DCP 沿 T 维度把 KV 在 CP rank 间**轮询交错**切分（每 rank 一次拿 `cp_interleave` 个 token 的 KV，再轮下一个 rank）：`vllm/v1/worker/gpu/cp_utils.py:51-58`；策略来自文档 `docs/serving/context_parallel_deployment.md:31`（Moonshot Chao Hong 的 interleaving strategy）。
- **不会破坏 prefix caching 正确性**：hash 基于 token ID，与 KV 物理切分无关；切分模式确定性→同前缀→同 hash→各 rank 同物理块命中。
- **缓存块粒度被放大 `dcp*pcp` 倍**以让一块前缀的完整跨 rank KV 作为整体引用：
  - `single_type_kv_cache_manager.py:145-146`：`block_size *= dcp_world_size * pcp_world_size`
  - `kv_cache_utils.py:630-632`：单 group 时 scheduler block size = `block_size * dcp * pcp`
  - `find_longest_cache_hit` 也用放大后的 block_size（`:649-651`）。
- **硬限制（直接不兼容）**：
  - Sliding Window：`assert dcp==1 / pcp==1`（`single_type_kv_cache_manager.py:766-767`）。
  - Hybrid 多 block_size 的 KV group：`raise ValueError`（不支持 CP，`kv_cache_utils.py:634-638`）。
- 实际影响：仅 MLA + 全文注意力（DeepSeek/Kimi）可共存，但短前缀复用粒度变粗（命中率下降）。

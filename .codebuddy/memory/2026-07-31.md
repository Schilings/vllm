## 补全 vllm_async_scheduler.md §4b.5.4：使用点为何能安全读
- 用户质疑（针对 gpu/model_runner.py:991-1007）：从 last_sampled_tokens 读 token 填 input_ids 时，上一步 fwd 可能还没结束，不会脏吗？
- 结论：不会脏，且无显式同步。三层保证：(1) 同一 worker 进程把 step N/N+1 的 GPU 任务都追加到同一 CUDA default stream，stream 内严格按入队顺序执行 → step N 的 post_update 写(:492) 必排在 step N+1 的 combine 读(:994) 之前；(2) last_sampled_tokens 按 req_state_idx 分槽，是跨步接力而非读自己；(3) 异步重叠发生在 CPU 调度器↔GPU 边界(batch_queue+Future)，worker 内 GPU 流始终有序。
- 例外：PP+async 跨 stage 无直接 token 通道，靠 next_decode_eligible_step(request.py:146) 错开。
- 已新增 §4b.5.4 + 目录链接 + FAQ Q9 固化。源码未改动。
